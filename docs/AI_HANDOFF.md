# 5分钟接手：实际公开项目，而非空框架

当前 v21 的 `baseline_kind=split_zip_descriptor`：`baseline_path`/SHA 指公开的分卷描述文件，不是完整 Blend 或首卷。验证两卷、拼接 ZIP CRC 和唯一 Blend SHA 后，在独立可写副本运行 `scripts/unpack_full_source.py` 恢复完整源；`materialized_baseline_path`/SHA 描述恢复结果。先验证洁净发布树，再在副本恢复，不把生成 Blend 当新增白名单文件。任务证据仍用公开描述文件 SHA 作为同一输入版本锚点。

1. 读`project_contract.json`，下载/检出它的`baseline_path`与`baseline_manifest_path`；跑`python tools/validate_contract.py --root .`。不可跳回首轮私有R3D SHA。
2. 完整Blender检查点是编辑输入；固定v03 GLB与`preview/patches.json`的按顺序执行的精确替换链继续作为不可变来源；新补丁可替换前补丁节点，不能只在 v03 名称表中找。网页默认用固定 `public_runtime_v14` 无损运行基底，再按顺序应用 v15、v16、v17、v18、v19、v20、v21 ZIP 增量；只信任完整 SHA 校验成功的缓存字节，不把旧 v14 基底单独称为当前 v21。失败不自动下载旧链，需明确选择完整旧加载方式；缓存不提升模型精度或保证内存/FPS。v04地表、程序树和可选自行车仍独立加载。不要只打开一个小补丁就以为整校资产丢失。
3. 阅读当前版本README、数据/来源/假设与QA。模型mesh数不是楼数；201源轮廓也含附属/组合体，不能当201座独立建筑。
4. `tasks.json`是可认领下一步，不是正在运行的worker列表。维护者初始化单一协调DB，worker只领一份明确模块。每项只写自己的prefix，冻结基底只读。
5. 真正做几何之前，核旧细部是否已经保留、名称/使用单位是否混标、是否把上层投影当实墙。产出独立小模块＋来源＋参数＋具体替换清单＋前后图，再独立review/唯一合并。

## 当前边界
- 公开模型已包含基底、旧细部恢复及逐版外观修正，不再是“只有框架无资产”。但仍不是全部实测/精修校园。
- 田家炳北条4排窗属于可见类型参考，不等于全楼4层；南旧高度/窗排仍估。金智的隔离旧核心诊断未进入v14，不要从未发布候选猜主图现状。
- 还有估高体块、近似C3/兰园/亭位置及两处低标记等。正式名称与功能、层数与米高、复用与实景验证分开记账。
- 泳馆门是外观门；体育馆上层平台、桥与台阶需要独立导航层/portal。候选路网不是已实现小人寻路，紧急出口不是普通入口。
- 网页 v0.21.0 保留质量优先与 v0.14.3 对数深度/单指平移、双指视角和缩放：默认原桥透射、全部 603 棵最高已有细节树、原生像素比（仅真 GPU 尺寸限制会提示降档）；省资源桥栏/画面只由用户手动启用。无损快照、几何不变合批及分层地表保留。体育恢复 404 件完整作者细部（排除 13 重复底板），60 个篮球组件仅共同下移 0.459 m 接当前显示地面，局部形状/材质不减；3 种程序 Noise/Bump 仅 Blender 原节点支持，不宣称 glTF 等价。v16 再补外围 18 场，当前桃园 30 场/60 个篮架，位置来自 30 个 OSM pitch，器材尺寸与外观仍估计；14 个宿舍窗梃做局部共面构造修正，不动原玻璃和墙。398 路微表面只有 2 条有明确材质标签，396 条是显示推定；B2 仅一个局部路段，别把 6 件独立结构层或周界显示裁边重复加载，也别当导航路网改造。钟山庭院仅施工照片支持的近似体量，不是精确竣工模型。解析测试不代替真实手机 FPS，高质量默认可能更耗资源。

- v17 九曲桥宽度 7.5m 是经用户视觉审阅采用的照片比例估计，不是测量；保原桥高、中心路线、完整栏杆/座凳和原材质。平面灰色铺装、四个接岸表达和四条道路显示面替换按实际清单有序执行，不复活红色立体波浪。v0.16.1 已让两盏原灯同时照 ground layer1 和 normal layer0；后续必须保留，否则 PBR 球场会无光变黑。

- v18 只修教学区 12 个原道路/接入段的同高顶面重复，保原路面并集、中心线、宽度与 Z；4 个指定内部主路（300162249、630432677、630432678、632703303）按用户现场说明作柏油色表达，不加人行道、不泛改全校。四个显示覆盖要在通用道路色后执行，且不能被异步植被重新着色覆盖；外围道路接头未在本轮全部修复。少 304 三角是去重复分区，不是 LOD 或删除有效路面。

- v19 基于 v18 完整源，仅替换桃园 1–2 八栋的 8 个旧屋顶，增加 48 个端部组件与田径场 16 个细部，主体 4260 mesh；4196 个原对象逐项保留。田径 12 个 surface_paint 必须按 extras 的 31/34/35/36 顺序走 ground pass，并保两灯照 layer1；4 个球门/网正常深度。原环面和 hole、导航与 v18 道路不改。八道有 OSM 依据，但 100×64m 布局、线宽、窗距和设施位置仍估计，不称精确 400m 或全校宿舍完成。

- v20 仅追加桃园田径场西侧大看台 16 个正常深度建筑对象，保原 4260 对象全部几何/世界矩阵/材料，当前 4276 mesh。OSM way1056927532 原六边形投影与 leisure=bleachers 标签解释此前遗漏；朝东看场地。主体 8.5m、顶棚约 12.5–14m、17 排/3264 模型椅均为照片辅助估计，不是实测容量或结构设计。看台不进入无深度 ground pass。

- v21 纠正桃园3–8的24条历史梯形配准，精确96同名替96，主体仍4276；其余4180几何及全部4276原PBR保持。来源是逐栋99%以上近矩形OSM投影，不应把其它真实不规则楼一律拉直。目标XY/拓扑改变、原Z界保持，质心最大回正约0.641m，不称原坐标零改动。正式patch从整合源保原材质导出，禁止用dorm24/corrected中统一roughness0.65的几何审查GLB替代。四楼艺术阳台/配色试验不在此批。旧110窗/五排仍继承估计，未完成逐栋差异化。

## 最小操作
```sh
python tools/test_coop.py
python tools/test_contract.py
python tools/validate_contract.py --root .
python tools/coop.py init --db coordination.sqlite --tasks tasks.json --root .
python tools/coop.py claim --db coordination.sqlite --task NAME-EVIDENCE --actor your-agent
```
用自己的真实产物填写evidence，然后submit；独立reviewer核看报告/图后review。不要提交这里的例子作为校园完成证据。

需要跨机器协作时由维护者认领PR串行授权；本仓库不提供全局锁或自动发布机器人。原始参考照片不必公开，公开事实/源轮廓和生成参数必须足以解释本次贡献。
