# 小人在路上走 / 跑：可实施的最小设计

本文件是后续阶段的设计建议，不是已实现或已验证的寻路/行人功能。当前网页没有启用这些小人行为，也不以用户另行提供的玩法文档扩展本轮开发。候选道路/节点来自现有OSM快照，需后续单独审核与实现。速度等是初始仿真参数，不是九龙湖现场人流测量。

## 1. 不把地图线条直接当导航图
已有388个线状道路候选，另10个面积/无中心线不能沿多边形边界走；其中18条带bridge、8条带tunnel。道路渲染Z只有毫米分层，无实际高程，**不能拿渲染Z判断桥上桥下**。

先以OSM源node id分段建立拓扑，同一node且同一通行层才能默认连接。不同way在二维投影上相交但没有共同node时只记“待审核交叉候选”，不自动连通。跨layer、bridge、tunnel边界必须显式portal；现有layer只是拓扑线索，实际桥面高度未证实前不造坡道。穿楼通道不能被楼的简单footprint一刀封死，需对应真实通道几何/净空核验。

保留 `highway / foot / access / oneway:foot / layer / bridge / tunnel`。优先footway/path/pedestrian；cycleway不能仅凭名称判断可步行，service/unclassified可作为待审核共享道路，不直接当安全人行道。steps只走、不跑；无障碍agent另禁steps。面积广场以后建局部navmesh，不能把周界当中心线。

## 2. 入口与投影
原快照现识别41个相关节点：12个gate、7个entrance=main、22个emergency:exit=yes。它们是有来源的候选，不是已核实当前开放入口；22个紧急出口不能用于普通人默认进入。当前楼入口未逐一证实，不能用建筑质心/最近路点制造“入口”。每个入口独立记录：building_stable_id、门洞XY、楼层、入口证据、走廊净宽、连接road_node/segment、启用状态。未确认楼只可导航到附近已知道路上的观察点，UI写“楼附近”，不穿墙到中心。

点击目的地先raycast已批准的可行走面：中心线路段用最近点+累计弧长投影；大广场用navmesh最近可走点。最大吸附距离先设8m，超过时要求用户选路，不能跨河/穿楼吸附。投影还必须检查同一拓扑层、点至候选连接的整个线段不穿障碍。入口portal在两种表征之间切换。

分层navmesh按地面/桥面/台阶独立生成，以真实测定或已核证的坡道和楼梯portal连接。屋顶、湖面、球场比赛区、工地不是默认通行面；水上桥属于独立层。基础道路宽度若为估计，要标注不确定并保守收缩，不能把整条机动车道当无风险可走区域。

## 3. 行为参数（建议默认值，后续可调）
- 步行1.2–1.5m/s，慢跑2.4–3.2m/s；加速度限幅，转弯减速，不瞬间从0切3m/s。
- 角色半径0.3–0.4m；窄路先排队、双向错身降速，尽量不靠障碍边缘。目标偏置从路径宽度裁剪，不抖动左右横跳。
- 台阶/急转/门口回到步行；跑步只在确认可跑路段，不能自动穿草坪抄近路。
- 过街通过显式crossing边；未知标线不凭空画斑马线。无车流实现时也保留“路缘停步—确认通行—过街”状态机。以后接车流才计算冲突间隙；没有交通控制资料不伪称信号灯模拟。
- 静态障碍由navmesh/走廊约束解决；动态小人用局部邻居网格+分离/速度避让，不为每个人每帧全校A*。树干需可碰撞，但树冠不用整球阻人；本轮树已在道路外，不应成为新的路线封堵。

## 4. 路径与tick预算（手机优先）
全局A*仅在目标改变、边封闭、角色长时间被堵时重算，按起终节点/路线模式缓存。沿路径用弧长运动，最后投影回走廊，不让每帧累计误差把人带入水面。

近处少量角色运动积分10–20Hz，画面按需要以插值更新；局部避让5–10Hz；远处角色1–2Hz更新弧长并简化显示。近处活动者先限32个，整个可见场景先限64，离屏角色只留逻辑状态；数字是初始工程预算，需实测，不是保证。

可见人在移动时才保持RAF；全部停止/页签隐藏/页面进入后台则暂停或降低tick，返回时限制补时步数，不能一次补跑几十秒。手机减少材质种类、共享骨架动画资源/实例动画；不要给每个小人独立高面数材质与阴影。

## 5. 首个验收闭环
只挑一条已核实平地步行路线（不先选跨桥/穿楼复杂段），明确两个入口/观察点。做单个行人→8人→32人的升级验证，再考虑全校。

必测：点湖面拒绝、点墙后不穿墙、面积广场不沿外框绕圈、桥上下不串层、台阶跑步自动降速、窄路会让行、终点重新点击平稳重规划、后台恢复不瞬移、缺入口只到楼附近、断路报告不可达而非穿越绿地。性能验收应记录目标手机浏览器的drawcalls、三角量、帧时P50/P95和内存；桌面headless结果不能当手机合格。

## 源字段恢复与权限优先级

原base文件过滤过tags，不能凭其缺少access就认定开放。候选JSON已从raw OSM way恢复foot/access/oneway:foot等字段。行人权限先看foot，再继承一般access；这是OSM的具体交通方式覆盖通用键规则，参见[OSM access说明](https://wiki.openstreetmap.org/wiki/Access)。现两条access=no且无foot放行的way（300165431、633558639）默认关闭。way1315044899虽access=permit但foot=yes，不误禁行人；这仍是快照标签解释，不保证现场当前开放。

门节点约束也必须生效：三个gate标有access=no及locked=yes；东北门gate标有foot=permit和05:00–22:00开放时间，不能只因道路边允许就穿过关闭门。条件/时间字段原样保留，未实现时保守要求审核。入口候选与路、楼共享节点关系已经存储，但没有添加任何虚构连接段。
