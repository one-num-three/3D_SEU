# v0.14 等价运行快照

这是模型 v0.14 的无损运行时派生包，不是新建模版本，也不代表全校完成精模。对应模型提交 `1a30a944d2dcd5a0b278330fa755268ddea89427`。原 v0.3 + v0.5–v0.14 补丁链、原完整 Blender 源和历史版本保持不变。

ZIP 单成员 `SEU_runtime_visible_v14.glb`：3976 作者节点、2589673 三角。移除的仅是原链明确替换的90旧块；全部1340新补丁节点保留。不把地表v0.4、程序植被v0.6和默认关闭的R1自行车烘入建筑。原材质扩展（含桥栏约0.96透射）、坐标、extras和稳定ID保留；低开销栏板仍由网页可逆克隆显示材质实现。

## 收益和限制
建筑下载文件体积从30,194,820 B降至14,292,437 B，约减少52.67%。这是资源body大小，不是含HTTP头和协商压缩的实测传输量。隐藏旧几何只减少456,984 B的独占属性缓冲；不宣称RAM大幅下降或手机FPS提高。完整解压GLB仍48,077,184 B，单次解压与解析也可能更慢。Node CPU/RSS估计在qa/，不是手机或GPU实测。

## 加载契约
`preview/runtime.json`声明schemaVersion1、模型0.14及来源commit；默认snapshot验证ZIP字节大小/SHA、唯一成员名称/大小/SHA、GLB内部格式/作者节点/名字后解析，成功才将场景交给主加载器。主加载器完成独立地表验证后一次加入场景，继续既有双pass、按需render、定位、树、可选车和合批功能。

失败不自动加载旧链。用户可以重试快照，或者明确选择“改用旧加载方式（约30MB建筑）”。旧链有自己的固定ZIP成员和补丁清单SHA。取消请求终止下载/解压；正在同步解析时会在返回边界检查取消并dispose已解析对象，不能承诺立即打断JS同步解析。释放引用后具体缓冲回收时机由浏览器GC决定。重试可由HTTP缓存复用网络响应，但每次仍重新校验SHA；没有额外持久JS原始包缓存。旧链故障也不偷偷切回快照。

## 重建
在含历史源目录的仓库根运行：
`python public_runtime_v14/scripts/build_snapshot.py`

脚本从data/SOURCE_CHAIN.json固定的来源hash和精确替换名单重建，验证每个源文件，不读取可变的最新preview补丁配置。只重排glTF引用、逐bufferView复制字节；没有重三角化/法线重算/几何简化。ZIP固定成员时间戳，重复重建字节一致。会在本目录assets/额外生成48MB原GLB用于核对，默认发布只包含小于25MB的ZIP，不要把生成的大GLB加入网页上传。data/SOURCE_NODE_MAPPING.json逐节点记录原资产、节点index和稳定ID（原缺失的ID不捏造）。

完整源Blend也可导出3976节点/同三角数，但其全量重新导出布局与原运行GLB不逐字节等价，因此本包使用原GLB无损组合，而非替换为重新导出结果。
